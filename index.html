One slow link can stall the entire ring

CHARM+ restructures distributed attention communication using hierarchical data movement, parallel streams, and online merging to reduce exposed communication.

01 / The bottleneck

Ring-Attention: one slow link blocks everyone

Sixteen GPUs form a single ring across two nodes. Each round transfers KV to the next rank. Intra-node links have variable arrival times, while the two cross-node boundaries are slower.

Intra-node link · fast Cross-node link · slow Finished GPU waiting

Illustrative bandwidth ratios, not measured hardware bandwidth. Intra-node links vary independently; cross-node links are slower. The synchronized ring round waits for the slowest transfers.

01b / Same ring · CHARM+ forward

Two layers instead of one ring

Same 16 GPUs on the same circle. But partners are no longer the adjacent rank: intra-node traffic rotates in staggered groups, cross-node traffic exchanges along columns (through the centre). Q, KV, column-Q and outputs each ride their own stream, so compute overlaps transfer.

Node A · staggered rotate Node B · staggered rotate KV stream Column-Q stream Output reduce

Column exchange runs through the centre hub; intra-node rotation never touches the adjacent rank. Radial spokes = cross-node columns, arc paths = intra-node staggered groups.

Sequential dependency

Ring rounds depend on previously delivered KV blocks, creating a chain of rank-to-rank transfers.

Exposed communication

Early arrivals may wait for slower transfers before dependent work can proceed.

Uneven link bandwidth

Cross-node links can dominate the time to complete each ring round.

CHARM+ / TWO-DIMENSIONAL COMMUNICATION

CHARM+: Hierarchical rotation + column exchange

Unlike a fixed neighbor-to-neighbor ring, this conceptual view combines skewed intra-node rotation, inter-node same-column exchange, and asynchronous attention/re-merge pipelines.

Hierarchical communication

Intra-node skewed rotation and inter-node column exchange replace a single fixed neighbor ring.

Multistream overlap

Q/KV movement overlaps attention computation; partial outputs and normalization statistics are merged online.

Tail-ring re-merge

Remaining blocks are processed and combined with asynchronously returned block and column-reduction results.

02 / The approach

CHARM+ does three things

Shorten communication dependency chains, overlap independent work, and isolate slow cross-node traffic.

Merge — logarithmic levels

Pairwise aggregation can reduce dependency depth compared with a linear ring walk. The exact schedule depends on the implementation.

RM+ — multistream overlap

Independent query and KV transfers can run alongside attention computation, reducing exposed communication.

Cross-Hardware — query parallelism

Cross-node query movement is decoupled from intra-node work so local computation can overlap slower transfers.
