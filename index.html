One slow link can stall the entire ring

CHARM+ (Cross-Hardware Attention with Re-Merge Multistream) restructures how distributed attention communicates: it shortens the dependency chain, runs independent streams in parallel, and hides cross-hardware traffic behind local work.

01 / The bottleneck

Ring-Attention: one slow link blocks everyone

Sixteen GPUs form a single ring across two nodes. Every GPU sends one KV packet per round. The round ends only when all 16 links have delivered. Intra-node links have different arrival times, but both cross-node links are substantially slower.

Intra-node link · fast (80–120) Cross-node link · slow (10) KV packet GPU waiting at barrier

Illustrative bandwidth ratios, not measured hardware bandwidth. Each intra-node link independently varies between 80 and 120 per round; cross-node links remain at 10. The global barrier waits for all 16 links.

Sequential dependency

Round k cannot begin until round k−1 is fully delivered on every link. All 16 transfers participate in the same global barrier.

Exposed communication

GPUs whose incoming packets arrive early wait at the barrier while the remaining transfers continue.

Uneven link bandwidth

Intra-node links differ moderately in speed; the two cross-node boundary links are much slower and dominate round completion.

02 / The approach

CHARM+ does three things

Shorten the chain, overlap independent work, and isolate the slow boundary.

Merge — logarithmic levels

Pairwise KV aggregation replaces the linear ring walk. The dependency depth drops from O(n) to O(log n) — four levels for sixteen GPUs.

RM+ — multistream overlap

Query communication is independent of KV communication. RM+ runs both streams at once so attention compute can overlap transfers.

Cross-Hardware — query parallelism

Cross-node query movement is decoupled from the intra-node pipeline, allowing local attention work to overlap slow boundary transfers.
